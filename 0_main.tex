\begin{abstract}
The terms of how publicly available source code can be used are dictated
by its license. The license (or its absence), in turn, affects what code
the project may reuse and how its code can be (re)used, and may also
affect external participation and overall activity of the project. We
study license distribution and impact in $131{,}171{,}379$ open-source
projects from World of Code (WoC). We find that $83\%$ lack a formal
license -- four times the rate reported by prior studies that filtered
on stars, maturity, or package-manager presence. Restrictive licenses
have higher retention rates; permissive licenses dominate new adoptions.
We then analyze the $23{,}619$ projects that underwent a license-type
change, modeling seven project metrics before and after the change with
a multivariate multiple regression. Once pre-treatment project
popularity (upstream and downstream project counts) is controlled, the
apparent global effects of license direction on files, upstream, and
downstream project counts collapse to non-significance. The robust
finding is language-ecosystem mediation: switching to a permissive
license is associated with reduced activity in C/C++ projects (commits
OR~$0.69$, files~$0.76$) and increased growth in Python projects
(files~$1.46$, blobs~$1.24$). Modest negative associations with commits
(OR~$0.83$) and sustained activity (OR~$0.92$) persist globally, and a
year-before/year-after reanalysis on the same projects confirms these
patterns are not an artifact of the baseline window.
\end{abstract}
